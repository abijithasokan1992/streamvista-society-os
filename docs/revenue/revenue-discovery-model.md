# Vista OS Revenue Discovery Model

## Mission
Turn Vista OS capabilities into the fastest credible path to revenue and profit.

## Classification Boundary — Mandatory
Revenue Intelligence operates with two strictly separate visibility classes:

### 🔒 INTERNAL / PRIVATE
Revenue discovery, profit analysis, opportunity scores, buyer intelligence, commercial-model analysis, unpublished products/services, pricing hypotheses, internal strategy, internal agents/workflows and founder/business intelligence.

### 🌍 PUBLIC / EXTERNAL
Only explicitly approved customer-facing capabilities, products, services, pricing, documentation, APIs and authorized account data.

**Public release is NEVER automatic.**

Required promotion path:
**INTERNAL-PRIVATE → INTERNAL-TEST → INTERNAL-VERIFIED → PRODUCT-APPROVED → PUBLIC-RELEASED**

No automatic crossover from internal/private to public/external.

## Commercial Model Selection
Vista OS must evaluate every opportunity across:
- B2B
- B2C
- D2C
- B2B2C
- Marketplace
- SaaS
- Service
- Product + Service
- API / Usage
- Licensing
- White-label
- Commission
- Freemium
- Enterprise
- Hybrid models

Do not choose the model before understanding the opportunity.

## Opportunity Pipeline
DISCOVER → UNDERSTAND → DECOMPOSE → MODEL → SCORE → VERIFY → PACKAGE → PRICE → SELL → MEASURE

## Sellable Units
Every capability must be tested as:
1. Single module
2. Standalone tool
3. Standalone app
4. API/service
5. Product
6. Product bundle
7. Managed service
8. Enterprise/white-label offering

Only separate a capability when there is a real customer/problem/distribution/revenue reason.

## Revenue Score
Score 0–100 using evidence:
- Buyer/problem strength: 25
- Speed to first sale: 20
- Implementation readiness: 20
- Profit/margin potential: 15
- Distribution advantage: 10
- Differentiation: 10

Priority:
- 80–100 P0 SELL/SHIP NOW
- 65–79 P1 PRODUCTIZE NEXT
- 50–64 P2 VALIDATE
- 30–49 P3 EXPERIMENT
- 0–29 P4 DEFER

## Profit Rule
Revenue alone is insufficient.

Estimated profit = selling price − delivery cost − acquisition cost − variable platform/fulfilment cost.

Rank opportunities using a combination of probability, expected profit and speed.

## Output Contract
Every INTERNAL Revenue Discovery result should be short and actionable:

**SELL THIS**
- Opportunity
- Customer
- Commercial model
- Price/range
- Estimated margin
- Probability
- Evidence
- Readiness
- Why now
- One next action
- Classification state

Public output must contain only approved customer-facing information and must not expose internal scores, unpublished opportunities, internal margins, buyer intelligence or strategic reasoning unless explicitly approved.

## Discovery Commands
Examples:
- Find today's biggest revenue opportunity.
- What can we sell today?
- Find the fastest path to ₹1 lakh profit.
- Turn this capability into a product.
- Find products we can sell B2B.
- Find D2C opportunities.
- Find service opportunities from this repository.
- Find the best bundle from these modules.
- Find licensing/white-label opportunities.

## Vista UX Law
The interface must feel simple and familiar: Vista-inspired visual character with XP-level ease of use. Complex intelligence stays behind simple actions.

## Evidence Law
Opportunity probability is not a promise or forecast. It must show the signals supporting the score. Opportunity ≠ verified deal ≠ collected revenue.

## Continuous Discovery
After every scan, continue looking for new products, services, tools, apps, modules, bundles, integrations and commercial models. Reuse existing capability before building new capability.
