# Vista OS Revenue Intelligence — Canonical Capability

## 1. Mission
Revenue Intelligence is the internal commercial-discovery capability of Vista OS.

Its job is to continuously discover, test, verify, package and prioritize **revenue + profit opportunities** from existing capabilities, repositories, products, services, tools, modules, integrations and new opportunities — while keeping internal intelligence strictly separated from public/external product surfaces.

**Core law:** Discover the opportunity first. Select the commercial model second. Build only what is required to capture verified demand.

---

## 2. Two-Layer Operating Boundary

### 🔒 INTERNAL / PRIVATE — default
Contains:
- Opportunity discovery and scoring
- Buyer/customer intelligence
- Profit and margin analysis
- Pricing hypotheses
- Commercial-model comparisons
- Unreleased product/service concepts
- Productization experiments
- Competitive/market reasoning
- Internal agents, workflows and automation logic
- Founder/business intelligence
- Internal evidence and decision history

### 🌍 PUBLIC / EXTERNAL — explicit release only
Contains only:
- Approved customer-facing products
- Approved services
- Approved pricing
- Public documentation
- Public APIs
- Public marketing claims
- Authorized customer/account data

**No automatic crossover.** Internal intelligence must never become public merely because an opportunity is verified or technically implemented.

### Promotion state machine
**INTERNAL-PRIVATE → INTERNAL-TEST → INTERNAL-VERIFIED → PRODUCT-APPROVED → PUBLIC-RELEASED**

A promotion requires explicit authorization at the relevant gate.

---

## 3. Continuous Discovery Engine

The engine must keep searching after each successful discovery.

**DISCOVER → UNDERSTAND → DECOMPOSE → REUSE → COMPOSE → MODEL → SCORE → TEST → VERIFY → PACKAGE → PRICE → SELL → MEASURE → DISCOVER AGAIN**

Search targets:
- Existing repositories
- Existing modules
- Existing applications
- Existing services
- Existing integrations
- Internal tools
- AI agents
- APIs
- Automation
- Media/creator capabilities
- Business operations capabilities
- Marketplace capabilities
- New external tools/apps/software/products that can accelerate or create opportunities

**Never stop at the first viable idea.** Continue finding additional independent and bundled opportunities until marginal expected value becomes low or evidence is insufficient.

---

## 4. Capability Productization Matrix

Every meaningful capability is tested in multiple forms:

1. Single module
2. Standalone tool
3. Independent app
4. AI agent
5. API / usage product
6. SaaS product
7. Product + service
8. Managed service
9. Bundle / suite
10. Enterprise deployment
11. Licensing
12. White-label
13. Marketplace / commission model

Do not split a capability merely because it can be split technically. Separation requires a credible **customer + problem + distribution + economic reason**.

---

## 5. Commercial Model Discovery

The system must evaluate, where applicable:

- B2B
- B2C
- D2C
- B2B2C
- Marketplace
- SaaS
- Service
- Product + Service
- API / Usage
- Licensing
- White-label
- Commission
- Freemium
- Enterprise
- Hybrid

**Model selection is opportunity-driven.** Do not assume B2B, B2C or D2C before understanding the buyer, problem, distribution and economics.

For each credible model, compare:
- Buyer
- Pain/problem
- Acquisition route
- Price potential
- Delivery cost
- Gross margin potential
- Sales cycle
- Implementation effort
- Repeatability
- Scale potential
- Evidence strength

Select the model with the best combination of **probability × profit × speed × strategic fit**.

## 6. Revenue + Profit Scoring

### Revenue Opportunity Score — 0–100
- Buyer/problem strength: 25
- Speed to first sale: 20
- Implementation readiness: 20
- Profit/margin potential: 15
- Distribution advantage: 10
- Differentiation: 10

Priority:
- **80–100: P0 — SELL / SHIP NOW**
- **65–79: P1 — PRODUCTIZE NEXT**
- **50–64: P2 — VALIDATE**
- **30–49: P3 — EXPERIMENT**
- **0–29: P4 — DEFER / ARCHIVE**

### Profit
Estimated contribution profit:

**Selling price − delivery cost − acquisition cost − variable platform/fulfilment cost**

Where evidence is missing, label the value as an assumption/range rather than a fact.

### Probability
Probability is an evidence-backed decision signal, **not a promise or forecast**.

Every probability must identify supporting evidence and uncertainty.

---

## 7. Evidence Gates

### Gate A — DISCOVERED
There is a capability/opportunity signal.

### Gate B — TESTED
The capability or commercial hypothesis has been technically or operationally tested.

### Gate C — VERIFIED
Evidence supports the capability, customer problem and proposed route sufficiently for internal decision-making.

### Gate D — PRODUCT-APPROVED
An authorized decision approves productization/public-release preparation.

### Gate E — PUBLIC-RELEASED
The customer-facing version is intentionally released.

**Catalogued ≠ Implemented ≠ Tested ≠ Verified ≠ Productized ≠ Public.**

## 9. Fastest-Result Principle

Revenue Intelligence optimizes for:

**Fast result + credible demand + profit + repeatability**

Not:
- maximum feature count
- maximum architecture complexity
- unnecessary rebuilding
- vanity metrics

**Reuse before build. Build gaps only.**

**Vista visual character + XP-level simplicity.**

---

## 12. Security / Separation Law

Revenue Intelligence is **INTERNAL-PRIVATE by default**.

No public user, external customer, partner or external agent receives internal commercial intelligence unless the relevant information has passed the explicit release gate and is authorized for that audience.

Customer data is isolated by authorization/account boundaries.

Internal and public datasets, views and outputs must be treated as separate classes even when generated by the same underlying engine.

---

## 13. Canonical Principle

> **One intelligence engine. Many opportunities. Many commercial models. Strict internal/public separation. Revenue and profit first. Simple outputs. Continuous discovery.**
